# Bazel Fundamentals - Level 9.2: The Generator (Problem Statement)

## The Scenario
The security team loved your graph-traversal proof of concept. Now they want the real thing. 

Instead of just printing the target names to the terminal, they want you to simulate a security scanner (like Trivy). For every single `cc_library` or `cc_binary` in the dependency graph, your Aspect must generate a physical text file named `<target_name>.audit` containing the target's label.

Because you are doing this via an Aspect, these `.audit` files will be generated in the "shadows"—completely parallel to the normal C++ compilation, without modifying the `cc_library` targets themselves.

## DevInfra Concepts: Shadow Actions & Output Groups

1. **Aspect Actions (`ctx.actions`)**
   Just like a standard Rule, an Aspect has access to `ctx.actions.declare_file`, `ctx.actions.write`, and `ctx.actions.run`. The files generated by an Aspect live in the exact same `bazel-bin/` directories as the target's normal outputs.

2. **Avoiding File Collisions**
   Because the exact same Aspect code runs on hundreds of different targets, you cannot hardcode a filename like `ctx.actions.declare_file("report.txt")`. If you do, multiple targets will try to write to the same `report.txt`, and Bazel will crash. You must use the target's unique properties to name the file:
   ```python
   out_file = ctx.actions.declare_file(target.label.name + ".audit")
   ```

3. **`OutputGroupInfo` (The CLI Hook)**
   If an Aspect declares a file, but nobody *asks* for that file, Bazel's lazy-evaluation engine will simply skip the action to save time. 
   To tell Bazel to actually build the file when requested from the command line, you must return a native Bazel provider called `OutputGroupInfo`. It maps a custom group name to a depset of files.
   ```python
   return [
       OutputGroupInfo(my_custom_reports = depset([out_file]))
   ]
   ```

### 3. Verification
Run this command. Notice the new `--output_groups` flag! This tells Bazel: *"Run the aspect, and explicitly build the files grouped under the name `audit_reports`."*

```bash
bazel build //:app_server \
  --aspects=//:my_aspects.bzl%security_scanner \
  --output_groups=audit_reports
```

**Success Criteria:** 
The build should succeed. Now, list the contents of your output directory:
`ls bazel-bin/*.audit`

You should see `app_server.audit` successfully generated. However, you will notice that `math_lib.audit` and `network_lib.audit` are **missing**. This is expected behavior! It proves that while Shadow Actions generate files, Bazel's lazy evaluation will instantly discard the dependency files unless they are explicitly aggregated.

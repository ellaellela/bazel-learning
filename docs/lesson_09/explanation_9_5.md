# Bazel Fundamentals - Level 9.5: Native Graph Pruning (Explanations)

## 1. The Solution

Here is the completed Starlark code for the optimized aspect:

```python
def _pruning_aspect_impl(target, ctx):
    print("Executing Starlark for:", target.label)
    return []

optimized_aspect = aspect(
    implementation = _pruning_aspect_impl,
    attr_aspects = ["deps"],
    required_providers = [CcInfo]  # The Graph Pruner!
)
```

---

## 2. DevInfra Theory: Native Graph Pruning

In Level 9.3, we used a Starlark-level filter:
```python
if CcInfo not in target:
    return []
```
While logically safe, this is a **Compute Drain**. If your binary depends on 5,000 text files, data files, and shell scripts, Bazel must instantiate the Starlark interpreter 5,000 times, execute the function, evaluate the `if` statement, and return `[]`. 

By defining `required_providers = [CcInfo]` in the Aspect declaration, you shift the filtering burden from your Starlark code to Bazel's internal Java engine. 

As Bazel walks the graph during the Analysis Phase, it checks the native provider dictionary of each dependency. When it sees `//:docs` does not possess `CcInfo`, it instantly severs that branch of the execution tree. The Starlark interpreter is never invoked, drastically reducing memory overhead and Analysis time on massive mono-repos.

## 3. Deep Dive: The Implicit C++ Graph

Look closely at the debug output generated by the build:

```text
DEBUG: Executing Starlark for: @rules_cc//:empty_lib
DEBUG: Executing Starlark for: //:core_logic
DEBUG: Executing Starlark for: @rules_cc//:link_extra_lib
DEBUG: Executing Starlark for: //:mixed_app
```

Even though you only explicitly wrote `deps = [":core_logic"]` in your `BUILD` file, the aspect traversed four targets! 

This reveals how `cc_binary` works under the hood. It secretly injects dependencies on the native C++ toolchain (`empty_lib` and `link_extra_lib`) to ensure cross-compilation works correctly. Because those implicit toolchain targets are C++ rules, they natively advertise `CcInfo`. 

Your `required_providers` filter handled this perfectly: it allowed the aspect to traverse the hidden C++ toolchain targets, but ruthlessly pruned the non-C++ `docs` target.

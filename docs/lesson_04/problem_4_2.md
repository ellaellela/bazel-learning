# Bonus Boss Fight 1: The Corporate Header Injector

## 1. The Scenario

Your company's legal department mandated that every JSON payload generated by the build system must begin with a standardized legal copyright header. 

You need to write a rule called `inject_header` that takes a single header file, a list of JSON files, and concatenates them into one output.

---

## 2. The Starlark Trap: Type Strictness

When you call `ctx.actions.run_shell`, the `inputs` parameter demands a single, flat Starlark list of all files that need to be mounted into the sandbox. 

If you try to combine a single file attribute (`ctx.file.header`) and a list attribute (`ctx.files.srcs`), Starlark will throw a type error because it does not do implicit casting. 

**The Fix:** You must wrap the single `File` object in brackets to make it a list of one, and then use the `+` operator to concatenate the two lists.

```python
# [File] + [File, File, File] = [File, File, File, File]
all_sandbox_inputs = [ctx.file.header] + ctx.files.srcs
```

---

## 3. The Implementation

### `my_rules.bzl`

```python
def _inject_header_impl(ctx):
    # 1. Declare output
    out_file = ctx.actions.declare_file(ctx.attr.out_name)
    
    # 2. Combine inputs for the sandbox
    sandbox_inputs = [ctx.file.header] + ctx.files.srcs
    
    # 3. Format paths for bash
    header_path = ctx.file.header.path
    srcs_paths = " ".join([f.path for f in ctx.files.srcs])
    
    # 4. Register the shell action
    ctx.actions.run_shell(
        inputs = sandbox_inputs, 
        outputs = [out_file],
        # Notice we are just concatenating, NOT minifying here.
        command = "cat {header} {srcs} > {out}".format(
            header = header_path,
            srcs = srcs_paths,
            out = out_file.path
        )
    )
    
    return [DefaultInfo(files = depset([out_file]))]

inject_header = rule(
    implementation = _inject_header_impl,
    attrs = {
        "header": attr.label(allow_single_file = True, mandatory = True),
        "srcs": attr.label_list(allow_files = True, mandatory = True),
        "out_name": attr.string(mandatory = True),
    },
)
```

### `BUILD`

```python
load("//:my_rules.bzl", "inject_header", "minify_json")

# 1. We create the legal file
# (Usually done by creating legal.txt in the workspace: `echo "// Copyright" > legal.txt`)

# 2. We minify the data
minify_json(
    name = "my_minifier",
    src = "data.json",
    out_name = "minified.json",
)

# 3. We inject the header into the minified data
inject_header(
    name = "compliant_combo",
    header = "legal.txt",
    srcs = [
        "//:my_minifier", # Passing the output of Rule 1!
    ],
    out_name = "compliant.json",
)
```

---

## 4. The DevInfra Takeaway: Separation of Concerns

Notice that `inject_header` does **not** run `tr -d ' \n'`. It just uses `cat`. 

If `inject_header` ran the minification command on its combined inputs, it would destroy the formatting of the legal header. By moving the minification logic to the upstream `minify_json` rule, we created a true pipeline. 

This is the exact architecture of a production build system (like compiling C++):
1. **Rule 1 (`minify_json`)**: Does the heavy transformation on individual files.
2. **Rule 2 (`inject_header`)**: Blindly links those transformed files together with a header.

They communicate entirely through Bazel's dependency graph.
